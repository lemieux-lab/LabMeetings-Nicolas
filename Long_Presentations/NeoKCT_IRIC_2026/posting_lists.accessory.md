# Figure: posting lists as a search engine index

Three panels. Left, the word x page grid nobody stores (illustrative words and pages, a few entries filled). Middle, what a search engine stores instead: one list of pages per word. Right, the same idea in NeoKCT: one list of (sample, count) pairs per fragment, using the k-mers from kct_overview.svg.
