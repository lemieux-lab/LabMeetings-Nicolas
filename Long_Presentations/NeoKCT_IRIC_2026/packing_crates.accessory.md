# Figure: bit packing as dropping leading zeros

Top row: eight counts from one block as plain 32-bit numbers, drawn as zero-padded 10-digit decimals (32 bits holds up to 4.3 billion, 10 digits). Second row: the same counts packed at 3 bits each because the block's largest count is 6 (110 in binary), with the binary written out below. Box widths to scale (3.5 px per bit), gaps between boxes are not. Explanation panel: one width per block keeps random access (entry i at i × width), each block picks its own width, sample numbers are gap-coded and packed the same way. Result line: about 2.6 bytes per (sample, count) entry with the fragment included, against about 8.5 for plain lists (7.78 TB / 909.7 B pairs).

Matches _pack_block! in NeoKCT src/KCTLayers.jl for the standard case: cbits = bit length of the block's largest count. Left out on purpose: cbits = 0 when every count is 1 (rare), and the 16-bit cap with the 0xffff sentinel plus per-block exception list for counts >= 65,535. Row lengths (lbits) not shown. Counts illustrative. Generated by make_concept_figs.py.
